How groups are formed
  1. Projects are deduplicated by canonical project ID. Cross-listed projects count once.
  2. Each displayed name gets one matching key: lowercased, with whitespace, hyphens and underscores removed.
  3. Projects with the same key form one group. Each project belongs to at most one group, and a group needs at least two distinct projects.
  4. Identical name: every project in the group displays the same name. Spelling variants: the displayed names differ.

Tags name what differs in a variant group: Case, Spacing (whitespace, hyphen or underscore) and Exact duplicates. A group can carry several tags, so tag counts do not add up. Other punctuation, spelling and sound-alike names are not matched. A shared key does not mean the projects are related.
