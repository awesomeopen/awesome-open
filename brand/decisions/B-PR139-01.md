# Verified name-change dates in specimen records

The owner requested a focused PR adding reviewed name changes to the existing
Repository record timeline. The explicit display rule is to plot real, verified
occurrence dates only; a date when the catalog discovered a change belongs in
secondary evidence, never in place of the event. This record captures the
approved scope; the draft implementation remains subject to PR review.

The [history contract](../../site/PROJECT-HISTORY.md) distinguishes software
renames, repository path changes and owner transfers. It records date precision
and basis; an implementation, announcement and release are separate evidence
milestones, not three rename events. Unknown and coarse occurrence dates and
first-observed/review dates stay in a folded Name-change evidence block.

This extends the repository timeline within B29 without replacing its plate or
changing B43's existing no-history layout. Records with history use one numbered
lane per dated point and a wrapping chronological list. Coincident dates keep
their true horizontal position; text is not crowded around markers. The axis
can extend before the current repository's creation without changing that fact.
The same record renderer serves the lazy drawer, full page and offline edition.

The two reviewed seeds are the [OpenTofu announcement](https://www.linuxfoundation.org/press/announcing-opentofu)
and [OpenHands implementation](https://github.com/OpenHands/OpenHands/pull/3472).
See the ledger for supporting sources, date meanings and review provenance.
The reusable data does not implement Observatory charts or an ex-Open archive.
No artwork, typography, eligibility, current names, aliases, project IDs,
collector budgets or schedules change.
