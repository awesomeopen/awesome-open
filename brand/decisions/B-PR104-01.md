# Visible result positions separate from alphabetical folios

Partial change to B32 in the [legacy register](../decisions.md): the default
cached-stars order and expanded alphabetical folios remain. Only the collapsed
ledger number changes meaning, from alphabetical position to position in the
current visible results. It starts at 001 and follows sorting and filtering.
The static default and standalone download use the same rule.

The row tooltip says “Position in current results”; the footer distinguishes
list numbers from Folio numbers. Expanded specimen labels and Field notes keep
the alphabetical folio. Registry IDs, canonical IDs, permalinks, aliases,
evidence and artwork are unchanged. No tokens, assets or skill pins change.

The two meanings are separated because alphabetical numbers appear scrambled
in a stars-sorted list and can look like ranking errors after a display-name
change. This is a bounded numbering change, not a ranking or identity change.

Implementation and regression coverage are in [PR #104](https://github.com/awesomeopen/awesome-open/pull/104).
The draft remains proposed pending review and merge; this record does not
relabel the historical B32 decision. Browser checks cover sorted and filtered
results, history, empty results, static fallback and the standalone download.
