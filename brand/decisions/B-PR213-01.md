# URL-only project submission plan

[The proposal](../../site/SUBMISSIONS.md) adds a bottom-of-Catalog URL field and a
small link to an accessible workflow infographic. It follows the existing
visual system and sibling-page shell. [WORKFLOW.md](../../WORKFLOW.md) records
today's research, acceptance, publication and later enrichment paths for the
image-generation handoff.

The [reference directory](https://www.mandalivia.com/cloudflare/) demonstrates
the low-input form pattern. Awesome Open* should accept an official homepage or
repository, derive the remaining fields through research, and give a durable
receipt before processing. Public issue storage, the receiver, its restricted
credentials and an explicit discovery consumer are proposed implementation
choices requiring separate setup and review. No live interface, task trigger,
service or permission is added by these documents.

The infographic must distinguish receipt from acceptance and deployment, preserve
the current direct-discovery/owner-merged-PR routes, and show enrichment after
basic catalog acceptance. Existing unknown-metadata and evidence semantics stay
unchanged. Implementation and generated artwork remain separate work.
