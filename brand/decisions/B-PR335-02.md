# The Catalog's WebMCPlet assistant is on as an experiment

The Catalog loads WebMCPlet with `data-webmcplet-assistant="on"` and the four cabinet tools
(`cabinet_arrange`, `cabinet_compare`, `cabinet_find`, `cabinet_inspect`). The search
dialog then offers "Ask Chrome's on-device model" where Chrome reports the model available
or downloadable; elsewhere the section stays hidden. The download starts only on a click.

This changes the part of [B-PR304-01](B-PR304-01.md) that kept the assistant off on the
Catalog. WebMCPlet's own default for other lists stays off
([webmcplet/README.md](../../webmcplet/README.md#assistant)).

**Evidence.** The latest measurement (2026-11-10, Chrome 156, on-device model
2025.8.8.1141, 20 runs per journey, pass threshold 17 of 20) passed the family-photo
journey (no match) 20 of 20 and the Markdown-editor journey 20 of 20. The video-editor
comparison selected the two requested projects in 8 of 20 runs; the other 12 selected
three ([experiments/prompt-api-m5](../../experiments/prompt-api-m5/README.md)). The
assistant stays below the threshold on that journey.

**Rationale.** Owner direction on 2026-11-15: Awesome Open is a test project, so visitors
with the model should be able to try the assistant. The existing guards stay: rows come
from tool results, the model's text is labelled as generated and withheld when it names an
item the tools did not return, and its cabinet calls appear as "Assistant" in the activity
log.
