# Experimental shared specimen cabinet

[PR #250](https://github.com/awesomeopen/awesome-open/pull/250) proposes a folded
Catalog instrument for an ordered selection of up to six projects, shared by
human controls and native WebMCP tools. The existing palette, typography and
ruled evidence language apply; mobile controls wrap and the comparison uses a
labeled horizontal scroll region. Existing artwork bytes and roles are unchanged.

The [cabinet contract](../../site/WEBMCP-CABINET.md) describes canonical-ID
validation, revision conflicts, atomic selection, cancellation, URL restoration,
bounded activity and source semantics. Unknown evidence keeps its status and dates.
The implementation shows tool execution activity; a full agent/client conversation
has not been tested. The existing Catalog, records and evidence downloads remain
the underlying sources. No new route, model service or collector is introduced.

The deferred personal/custom Scoreboard is recorded in [TODO.md](../../TODO.md)
for reconsideration around 1,000 projects and richer evidence coverage.

Native discovery and execution were verified on installed Chromium 154 with
WebMCP enabled on secure localhost. Human reorder was observed by native tools,
and both page and caller cancellation preserved selection. Desktop and 390px
captures were inspected. Native browser support is experimental; the browser
notice describes actual registration availability.
