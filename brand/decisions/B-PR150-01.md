# Reviewed renames join the existing repository timeline

The owner reviewed the numbered history lanes from
[B-PR139-01](B-PR139-01.md) on the OpenTofu record and found the earlier
repository timeline better. This course correction replaces only that display
rule; B-PR139-01's evidence rules (verified exact occurrence dates only, date
bases, folded evidence for unknown/coarse dates) stay in force, so the
supersession list is empty.

Records with a reviewed exact rename date now use the same creation/release/push
timeline as every other record. The rename adds one marker at its true date and a
label above the axis in the owner's requested form, for example
"Renamed: OpenDevin → OpenHands (i)", with the date below. The "(i)" is a native
disclosure that opens all details: kind, date basis and date, note, every source
link and review provenance. It currently opens in place below the label; a popup
and a drawn info icon are planned. A drawn icon first needs its row in
`brand/icons.md` and `site/brand/icons.json`. Close upper labels climb a row
instead of moving markers, and rename labels sit above the release label because
label widths are unknown on narrow screens. The numbered markers, chronological
list and history anchors are removed. The rename marker is a diamond; its label
text carries the meaning, not its shape or colour.

The owner also asked to remove sentences that disclaim claims the record never
made, such as "This is not a claim about the exact public announcement or GitHub
repository-transfer time." Both seed notes lose such sentences, and the history
contract tells reviewers not to add them. A broader sweep of that phrasing is
separate work.

Verification: the offline history tests and the full Chromium browser suite,
including the rewritten history check at 1440px and 320px in drawers, full
records and standalone output. No artwork, data sources, eligibility, names or
IDs change.
