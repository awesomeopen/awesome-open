# Icon map corrections: aged badge at 12px, hand-written SVG, no FOSSoligy

Partial change to [B-PR101-01](B-PR101-01.md); its other rules stand, so it is
not superseded. Applies to the [icon map](../icons.md) and its
[manifest](../../site/brand/icons.json).

## Changes

- **Aged at 12px.** B-PR101-01 said the 12px size never uses the aged badge,
  yet listed `state.aged` at 12px with a badge in its shape. Without the badge,
  aged and current differ only by colour, which breaks the map's own shape-first
  rule. Now `state.aged-s` uses a solid 4px dot in the badge position with a 1px
  paper knockout; 16 and 24 px keep the clock badge. `badge.aged` stays 16/24 only.
- **Production.** Replaces “generate a 96px sheet, then trace” with hand-written
  SVG per size on its own pixel grid, `currentColor` only. Image generation is
  optional only for 24px setup icons (`run.*`, `install.*`) when pencil character
  is wanted, saved as `{id}-l.webp` with prompt and tool in provenance.
- **Skill routing.** Interface icons are literal glyphs, not specimens. The
  Speculative FOSSoligy skill does not apply to them; Retro-Scraperism gives the
  interface context. Recorded in the map and in [illustration](../illustration.md).
- **References.** Code references re-audited against main `a9455b9`; most
  `scripts/build_site.py` lines had moved by four. Meanings, labels, IDs, tokens
  and sizes are otherwise unchanged.

## Evidence and limits

- User-directed after review of the drawing handoff for B-PR101-01, which found
  the 12px conflict and the skill mismatch.
- Documentation only: no artwork, generator or CSS change. Legibility of the
  4px dot at 12px is untested until icons are drawn.
- B-PR101-01 keeps its recorded status; this record does not change it.
- Originated in [PR #102](https://github.com/awesomeopen/awesome-open/pull/102).
