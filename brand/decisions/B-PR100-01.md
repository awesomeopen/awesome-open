# PR-scoped brand decision identities and generated overview

New decision IDs use the originating pull request's number and a per-PR ordinal.
Each record lives in its own matching Markdown file; the combined overview is
built from those records and the unchanged legacy register. No shared counter or
hand-edited overview is involved. IDs and paths remain stable after merge.
Replacement decisions declare their targets in `supersedes`; their own status
and evidence determine whether a replacement has actually been accepted.

The owner requested this focused workflow change after concurrent PRs reused
legacy numbers. Implementation remains proposed for review in
[PR #100](https://github.com/awesomeopen/awesome-open/pull/100).
The [authoring guide](../DECISION-GUIDE.md) defines metadata and validation.

The migration preserves all B01–B44 legacy entries, wording, links and statuses
from main `f44054ee109cc38eb984e00eafacefdbd612348c`, including the B42 route-shell
anchor and B44 from PR #97. This adds identity rules to the existing maintenance
workflow without superseding its brand choices. Older PR descriptions can still
contain pre-merge numbers; their historical wording is not rewritten here.

Trade-offs: a useful initial commit and early draft PR are needed to obtain the
number, and the complete overview is a generated CI artifact/local file rather
than a tracked table. Offline checks establish structural consistency, not
whether a proposal was approved or its design is sound. No installed skill,
asset bytes, hosting or repository settings are changed.
