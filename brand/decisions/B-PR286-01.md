# Verify recovery storage before artwork generation

[PR #286](https://github.com/awesomeopen/awesome-open/pull/286) adds a storage
preflight and per-image checkpoints to the recoverable-original requirement in
[B-PR232-01](B-PR232-01.md). The owner requested a resilient pipeline before
recreating an interrupted artwork batch. A storage failure should stop generation
before another image depends on an unverified destination.

The [recovery procedure](../../automation/artwork-recovery.md) requires an actual
upload/download probe before generation, original preservation before the next
image, separately verified finalization archives, and a durable batch index.
The offline helper records exclusive reservations, validates archive hashes and
restoration receipts, and compares candidate assets and records with recovered
finalization bytes. The operator performs the authorized external transfers and
preserves the index outside the disposable workspace.

Per-image archives keep transfers below 32 MiB and permit recovery without a
single large batch file. Receipt identity, quota safety and interrupted-state
checks fail closed. Real source/pixel/rights/safety review, independent recovery
storage, current-main checks, exact-head CI and the existing publication gates
remain required. External storage availability is an execution prerequisite;
local fixture tests exercise only the helper.

This partially refines the workflow in B-PR232-01. Existing asset roles,
illustration style, accepted artwork, schedules, pinned skills, settings and
publication authority are unchanged. This policy/code PR awaits owner review.
The repository's brand router is updated with the handoff; its installed mirror
is synchronized only after a reviewed merge.
