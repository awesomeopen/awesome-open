# New image files for payload reduction get their own PR

Owner-directed on 2026-10-22, when reviewing the open items of the
[performance PRD](../../PRD/2026-10-22_Performance-tuning.md#w4-payload-reduction-phase-3).
Phase 3 of the performance work adds new image files: responsive specimen
artwork at 512/768/1254 px, and possibly a change to which of the original and
the cutout ships. These go into a PR of their own with its own review, separate
from the data-only payload changes (compact site JSON, one owner for star
history).

That PR follows the existing derivative pattern of `site/jars/responsive/`:
provenance for every derived file, an update to [brand/assets.md](../assets.md)
and a refreshed `brand/assets.lock.json`. Reviewers inspect the actual images.

## Status

Accepted. [PR #184](https://github.com/awesomeopen/awesome-open/pull/184) records this
decision and changes no image files.
