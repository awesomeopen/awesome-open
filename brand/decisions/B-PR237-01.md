# Reviewed spelling equivalence and repository-path observations

Shared-name groups can use code-reviewed equivalences between current displayed
names, with explicit plural or spelling reasons. The initial registry preserves
OpenTask / OpenTasks. Exact normalized names continue to group automatically;
one-letter-edit suggestions require review before entering that registry.

The validated annotation supplies the same matching key and reason to Python and
JavaScript. Official names bind each registry entry to its existing catalog URL.
A changed name requires a new review; former-name aliases stay outside current
name grouping. The Spelling tag uses the existing tag treatment and introduces no
new icon or asset.

The existing GitHub metadata fetch also retains repository ID, requested and
resolved paths, URL and observation time. Path differences become review
candidates. A changed known repository ID stops cache replacement for review.
Software-rename dates still require official implementation or announcement
evidence; an endpoint observation records when it was checked.

See [Observatory accounting](../../site/OBSERVATORY.md#accounting) and
[repository-path review candidates](../../site/PROJECT-HISTORY.md#repository-path-review-candidates).
This proposal changes the review method and its literal labels, while preserving
Registry IDs, curated catalog records, the publisher schedule and existing
artwork. It contains no project-specific rename correction.
