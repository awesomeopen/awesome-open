# Reader-focused documentation with Curb your verbosiasm

Add [Curb your verbosiasm](../../.agents/skills/curb-your-verbosiasm/SKILL.md)
for Awesome Open* documentation, knowledgebase articles, help text and explanatory
interface copy. The owner requested a skill that starts with the main point,
makes it useful in fewer words, and uses a short example when that saves
explanation. Awesome Open* remains a list of software named Open; the reader's
task determines how much of its implementation to explain.

The workflow reads the whole passage, identifies the reader's question, leads
with the answer, and removes repetition before editing individual sentences.
Preserve evidence meaning, source links, dates, uncertainty, requirements and
verification status. Apply word-pattern review after this structural pass.

This extends the positive-statement guidance recorded in
[B-PR152-01](B-PR152-01.md). The skill maps the existing rules and targeted
source/browser checks, including monthly stars and stale metrics. Repository
and prior-context searches located the earlier cleanup in instructions,
generators and regression tests; a reusable rewrite script was not located.

The owner named [rand/cc-polymath's anti-slop skill](https://github.com/rand/cc-polymath/tree/main/skills/anti-slop)
and [petergyang/no-ai-slop](https://github.com/petergyang/no-ai-slop) as influences.
Their inspected file identities and the adapted principles are recorded in the
skill's [repository reference](../../.agents/skills/curb-your-verbosiasm/references/repository.md).
The instructions and examples are project-authored.

The owner requested an installed skill and a repository copy. The Skills
workspace holds the original; [skills.lock.json](../skills.lock.json) records
its source revision and checksums for the complete repository snapshot.
[Skill ownership](../skills.md) describes deliberate updates. The installed
skill is available for explicit use; repository adoption proceeds through
[PR #193](https://github.com/awesomeopen/awesome-open/pull/193).

Validation includes the skill validator, brand integrity, brand-decision tests,
and independent editing exercises. An initial exercise dropped an explicit
untested-installation fact. The revised instruction requires that status to
remain explicit; a fresh exercise preserved it along with unknown compatibility,
hardware requirements and stale-value dates. The exercise also confirmed that
already-clear copy can remain unchanged. These samples provide bounded evidence
of the editing workflow. Runtime UI copy and data remain under their existing
source and review contracts.
