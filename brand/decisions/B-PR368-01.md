# Retained collection activity in the moss block

The user requested a first collection-log version derived from retained evidence,
with small dated terminal lines and a readable `i` overview. Sparse or old activity
gets no badge, warning or judgment; visitors can read its timestamps.

This changes only the reserved HN/Scorecard cell from
[B-PR158-01](B-PR158-01.md), preserving its moss colour and the surrounding grid.
The real block remains visible on mobile. Three monospaced lines replay at six
second intervals while visible. Interaction, hidden tabs, closed plates and
reduced motion pause replay. Zero or one retained event stays static. The native
disclosure supplies an accessible chronology; replay creates no live announcements.

The [collection-log contract](../../site/COLLECTION-LOG.md) defines date meanings,
provenance, bounds and lazy delivery. Four recent events keep the terminal replay bounded. The disclosure loads all
retained dated events from a separate per-project file, with no display cutoff. It uses completed chart observations, metadata collection
attempts/successes and curated review dates. Build time and rename occurrence dates
never imply collection time. No collector, external service or invented activity
is introduced. A complete inclusion-to-present audit remains outside this version.

Only recent date/label pairs appear in record HTML. Complete chronology is fetched
on first disclosure, shared by drawers and standalone pages. The documented capacity
review adds 2 KiB/project to the non-artwork allowance; all other limits remain. Desktop and mobile captures were inspected with installed Chromium through
Python Playwright. The lighter moss treatment preserves small-text contrast.
Hosted browser validation and its final result are recorded in the PR.
