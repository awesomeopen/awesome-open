# Quarantine terminal artwork failures

[PR #323](https://github.com/awesomeopen/awesome-open/pull/323) extends the
[recovery procedure](../../automation/artwork-recovery.md#quarantine-a-terminal-project-failure)
with a separately restored hold for a terminal project rejection that returned
no artifact while backend output remains unknown. The owner asked to resolve the
recovery blocker and continue the artwork automation on November 12, 2026.

The hold preserves the original plan, reservation and complete failure evidence.
It keeps the failed project unresolved and blocked pending review while other
reserved projects continue after storage verification. The publication index
accounts for holds separately from completed artwork and known-no-output skips.
Candidate verification forbids artwork for a held ID and checks its restored
archive. Quarantine never authorizes a rejected operation to be retried.

This partially refines [B-PR318-01](B-PR318-01.md)'s uncertain-output stop. Pending
requests, timeouts, shared storage/access failures and known generated originals
still require their existing recovery steps. Existing receipts and successful
originals remain preserved. The helper validates structure and bytes; the
operator verifies the terminal response and absence of returned artifacts.

No asset, visual style, schedule, credential, live batch state or publication
authority changes in this PR. Its code and policy await owner review before use.
The repository router follows the procedure; its installed mirror follows only
after merge.
