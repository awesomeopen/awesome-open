# Icon map for evidence states, links, controls and setup facts

One icon map covers the evidence and detail boxes on the specimen plate and the
Observatory: the [icon map](../icons.md) and its machine-readable
[manifest](../../site/brand/icons.json). Both carry the same 50 IDs. 21 are for
labels rendered at the audited revision; 29 are planned.

## Rules

- Icons describe evidence state, never project quality. “Failed” means our
  retrieval attempt failed; a value such as a Scorecard score gets no state icon.
- Shared ring-based states (current, aged, partial, pending, none, failed,
  unknown) serve retrieval checks, repository-metric freshness and Observatory
  coverage. Human review uses a square base. Aged is an overlay badge, not a
  traffic-light midpoint. Unknown is muted and dashed, never negative.
- Shape carries meaning; tokens confirm it, and colour never carries state alone.
  Amber is not an icon stroke (about 1.6:1 on white).
- Three display sizes (12, 16, 24 px) from 96 px masters; small sizes as
  `currentColor` SVG.
- Verdict, security, rating and vendor glyphs are excluded. The existing loupe,
  botanical mark and fruit are unchanged.

## Evidence and limits

- User-directed request for a generalised icon map covering today's needs and
  likely additions. Audited against main `4bc3d97`; source references in the map
  point to that revision and drift as code changes.
- Applies the existing guide's status and colour rules
  ([Retro-Scraperism guide](../../site/RETRO-SCRAPERISM.md)) and token values
  ([tokens](../../site/design/tokens.css)).
- Documentation only: no artwork, generator or CSS change. Only part of the
  source references were spot-checked; legibility at 12 and 16 px is untested
  until icons are drawn.
- Originated in [PR #101](https://github.com/awesomeopen/awesome-open/pull/101).
