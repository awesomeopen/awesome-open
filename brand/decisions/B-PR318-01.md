# Continue artwork batches after verified project skips

[PR #318](https://github.com/awesomeopen/awesome-open/pull/318) adds a verified
skip checkpoint to the [artwork recovery procedure](../../automation/artwork-recovery.md#skip-one-blocked-project).
An isolated project failure with known no output can be recorded and skipped so
later projects proceed. The owner requested this backfill behavior on 2026-11-11.

The checkpoint preserves the original reservation, exact failure record and
supporting evidence. Its upload and independent restore must be verified before
the next generation. Existing successful receipts retain their plan identity.
The publication index accounts for every planned ID as completed artwork or a
verified skip, and candidate verification checks all restored archives.

This partially refines the serial gate in [B-PR286-01](B-PR286-01.md). Shared
storage/access failures and uncertain generation outcomes still block dependent
work. Skips last for one batch; later selection reviews the prior failure.
Retrying a denied operation requires materially new relevant evidence and the
required authorization. The offline helper validates structure and bytes; the
operator establishes the actual failure scope and output outcome.

The proposal changes no accepted assets, image style, schedules, settings or
publication authority. Live batch state remains unchanged. The repository brand
router is updated; its installed mirror follows only after reviewed merge.
Existing recovery checks and the art-only publication gate remain in force.
